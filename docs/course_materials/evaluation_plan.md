# 评估方案：准备阶段

状态：真实模型not_run，内容评分pending，人工来源评审pending，留出题尚未提供。原生成方案见`evals/code_artifact.md`，执行时以本修订版为准。

## 要求与安排

教师要求来自本地三份原课件：8–10道已知答案题，预先确定证据，保留2–3题最后测；诊断至少一条真实失败，记录改动、理由与结果；检查工具应调用、不应调用及失败处理。最终报告评价设计决策、测试与批判性分析。

本组采用7开发知识题＋3留出知识题的安排。留出题由独立组员保管，本目录不包含题目或答案。开发知识题JSON和ID不变。额外7道真实E2E开发题、1道离线故障项分组统计，不将模拟客户端结果混作真实模型表现。独立人工复核是本组证据质量安排及reviewed_development模式前置条件，不冒充教师指定的唯一流程。

## 运行条件

- 每道知识题新建ChatSession，selected_query=None；由现有runner完成。
- 每道E2E题开始前新会话；网页中刷新或重置后核实历史为空，再设置并应用CSV规定的侧栏条件。E2E02依赖页面选择，普通CLI ask没有selected_query参数，不能原样替代网页运行。另存问题、实际选择和trace；分享模式默认仅保存元数据，不足以作为完整内容评分证据，应使用可信本地测试并保存所需记录。
- 记录实际模型、API端点（不含密钥）、语言、执行日期和Berlin时区。不修改系统时钟；“昨晚”的D为实际执行当天醒来日。
- 记录工具状态和最终agent_status；不要求每个用例恰好使用示例query原文，等价且取到所需证据即可。修复重试在预算内允许，须记录额外请求和费用。
- 每轮最多3次模型请求、2次证据工具执行、整体60秒。默认开发批次最多21次请求、60000已知tokens；后者响应后检查，可能越过阈值后停止，不能保证7题全部完成。

## 执行顺序

1. 核对02的标准答案，由组员如实填写原生来源审阅表；AI辅助核对不能代签。未完成时用pilot模式。
2. 整理文件后创建新的候选baseline，不覆盖旧候选；执行dry-run。此次预检查的实际路径见08文档。
3. 真实运行需执行下面的live命令。它会消耗API额度，本次文件整理不执行此命令：

```powershell
.\.venv\Scripts\python.exe evals/run_formal_evaluation.py --live --stage pilot --baseline artifacts/candidate-v25-20261114-01.json
```

4. 从实际report中确认执行了几题，是否预算停止，是否有unknown usage。若仅执行子集，保持原计划7题和停止记录，不能把该轮称为完整评估。重跑/补跑单独记录run_id和所有费用；不要择优拼接成绩。跨运行汇总需预先声明每题采用哪一次结果。
5. 对照05逐题评分。按照03运行7道真实E2E题；E2E06用隔离测试桩验证，单独报告。当前未新增E2E自动runner，CSV是人工执行说明。
6. 找到真实失败后填写06，保存原trace。针对诊断做一项主要修改，保留精确diff；创建新baseline，同题复测及开发集回归。若没有失败则如实记录，再增加公开开发边界题，不伪造失败。
7. 最终候选冻结后，由保管组员执行留出题。提前用于修复的题转开发题，另补留出题。当前脚本拒绝非development集合，留出测试须由组员单独执行。

## 保存与版本

每轮自动输出`artifacts/formal-evaluations/<run_id>/report.json`、`review.csv`与`traces/`。原始产物只读保留，填写评分用副本。保留baseline、工作表版本、修改diff与评分理由。主baseline不会覆盖所有评估脚本和工作表，因此另保存本目录的准备清单哈希，不能将其称为最终候选冻结。

收费测试前核实候选仍匹配。代码、prompt、Skill、知识库、题集变化需新候选；评估脚本或评分口径变化也必须记录，不能视为相同实验条件。题集结构校验通过和dry-run成功均不提供语义准确率。
