## 1. 问题定义与产品设计（Design & Value Proposition）

### 1.1 目标用户与核心痛点
* **目标群体**：18–60 岁、使用消费级智能穿戴设备记录睡眠但缺乏专业解读能力的一般成年用户。
* **核心痛点**：
  1. 原始睡眠指标（时长、浅睡/深睡/REM 分钟数、夜醒次数）缺乏上下文，用户容易产生不必要的健康焦虑或误将单晚波动视为疾病诊断。
  2. 记录缺失（如未佩戴设备）常被误算作零睡眠，或在样本不足时强行对比前后两周导致误导性趋势判断。
  3. 通用聊天机器人缺乏本地记录读取能力，且容易在无依据时编造临床阈值、给出个人用药或睡眠限制处方。

### 1.2 为什么通用聊天机器人不够（战略护城河与边界）
* **结构化计算与业务规则强制隔离**：通过只读分析工具 `analyze_sleep` 执行确定性统计（如醒来日归属、跨午夜钟表时刻均值、有效夜数覆盖率与 4 晚产品展示门槛），避免大模型在算术统计或缺失值处理上产生幻觉。
* **受控知识与引用溯源**：将 SleepLens 专属字段/展示规则（B 类：B1、B2）与权威健康资料整理（H 类：CDC、NIH/NHLBI、NHS、AASM 等 H1–H11，共 38 段，版本 `sleep-knowledge-v6`）分离管理，要求所有事实声明绑定内部引用 ID（如 `[H8:NightWaking]`），且禁止在正文中暴露内部检索键名。
* **清晰的能力与安全边界**：原型明确限定为信息解读与一般教育，不连接真实硬件、不保存个人真实医疗档案（仅使用合成演示数据 `synthetic-sleep-v2`），拒绝医疗诊断、个体用药剂量调整及自主睡眠限制处方。

## 2. 系统架构与核心实现（Implementation）

### 2.1 技术栈与运行架构
* **前端与交互层**：基于 Python 与 Streamlit 构建网页交互界面（`app.py`），支持中英文切换、侧栏档案（`P01`、`P02`、`P03`）与日期范围选择，以及纯本地计算浏览（不消耗模型调用额度）。
* **指令与技能规范层**：
  * **系统指令**：`system_v25.md`（`prompt-v25`），负责确立角色定位、证据优先级、引用渲染规范及候选输出被拦截后的修正行为。
  * **业务技能**：`sleep-analysis`（版本 `3.0.1`），定义意图分类、日期/档案消歧规则、工具调用契约，并按任务动态加载 `references/` 下的子模块（`records`、`health`、`combined`、`sources`、`capability`、`followup`、`source_comparison`、`measurement_interpretation`）。
* **双轨知识架构（Hybrid Knowledge Architecture）**：
  * 尽管 `knowledge.py` 中 `KnowledgeBundle` 的默认类属性标注为 `full_context`，但实际运行时采用“规则注入 + 本地检索”的混合模式：
    1. **产品规则注入**：B 类文档（`B1.md` 记录定义、`B2.md` 分析与服务规则）作为产品语义基础直接注入上下文。
    2. **健康知识本地检索**：H 类文档（`H1.md`–`H11.md`）通过 `search_sleep_knowledge` 执行确定性本地主题匹配（`TOPIC_TERMS`）与关键词打分检索，结合核心锚点（`anchors`）去重互补，单次最多返回 4 段带有 `citation_id` 的段落（非实时联网检索，亦非向量库）。

### 2.2 确定性只读工具接口
1. **`analyze_sleep`（个人记录统计工具）**：
   * **必填参数**：`profile_id`（枚举 `P01`/`P02`/`P03`）、`start_date`、`end_date`（`YYYY-MM-DD`，仅支持单日 `start_date == end_date` 或连续 7 天 `end_date == start_date + 6天`，且结束日须早于 `Europe/Berlin` 当地当前日期）、`compare_previous`（布尔值，单日必须为 `false`）。
   * **核心计算口径**：
     * **醒来日归属**：睡眠记录按最终醒来当地日期归档（如 20 日晚入睡、21 日醒来归入 `2026-10-21`）。
     * **缺失与有效零值**：`sleep_valid=false` 时 `sleep_min` 必须为 `null`，不参与均值分母且降低覆盖率（`coverage = valid_nights / 1 或 7`）；有效的 `0` 分钟记录保留并计入分母，但触发 `zero_value_requires_verification` 提醒。
     * **四晚展示门槛**：两周比较（`difference_min = current_mean - previous_mean`）仅在两期各自拥有至少 4 晚有效记录时返回差值；否则返回 `comparison_state=insufficient_data` 与 `difference_min=null`，禁止模型自行相减或推断趋势。
     * **详细指标覆盖率**：`detail_nights` 仅统计有效且 7 个详细字段（`sleep_onset`、`wake_time`、`night_awakenings`、`awake_min`、`deep_sleep_min`、`light_sleep_min`、`rem_sleep_min`）均非空的夜晚，作为详细均值的统一分母。
2. **`search_sleep_knowledge`（本地循证知识检索工具）**：
   * **必填参数**：`query`（1–500 字符的非空字符串）；支持应用层传入只读控制参数 `excluded_topics` 与 `query_override`。
   * **返回状态**：`ok`、`no_results`、`invalid_input` 或 `tool_error`。

## 3. 安全、隐私与防护机制（Security, Privacy & Guardrails）

### 3.1 数据隐私与合成数据隔离
* **零真实健康数据**：系统仅加载离线合成数据集 `synthetic_sleep.json`（`synthetic-sleep-v2`，共 3 个虚构档案、42 条记录，覆盖 2026-10-12 至 2026-10-25），不包含真实患者/用户身份或设备同步接口。
* **密钥与敏感信息脱敏**：评估与运行日志写入前通过 `redact()` 过滤 API 密钥；评估脚本 `prepare_evaluation.py` 明确隔离 `.env`、`.state` 及留出题文件，防止敏感配置进入版本快照。

### 3.2 工具调用安全与注入防护
* **严格参数白名单校验**：`dispatch_tool` 使用 `_unique_arguments` 拒绝重复 JSON 键，严格校验工具名称与必填参数集合（`additionalProperties: False`），所有工具均为只读操作，无任何文件写入或外部网络请求权限。
* **提示注入边界隔离**：知识库上下文与工具返回在传入模型消息时附加 `"REFERENCE DATA ONLY (not a user request):\n"` 前缀，防止文本内容被模型误执行为控制指令。
* **CSV 公式注入防护**：`export_review()` 在导出评审表时对以 `=`、`+`、`-`、`@` 开头的模型输出添加单引号前缀，防止在 Excel 中打开时触发公式执行。

### 3.3 输出核验与回退防护（Validation & Fallback）
* **引用结构校验**：`KnowledgeBundle.check_citations()` 提取回答中所有 `[SourceID:Section]` 格式标签，拦截不存在的 ID（`invalid`）、本轮未提供给模型的 ID（`unavailable`）以及裸文档 ID（如 `[B1]`）。

## 4. 评估方法与实验结果（Evaluation）

### 4.1 评估目标与基线版本控制
* **评估目标**：验证 SleepLens 在**知识循证问答**与**端到端记录解读**两类任务上的证据获取率、主张支持度、引用准确性、缺口保留（Abstention）能力及工具调用合规性，并测量真实模型的延迟与 Token 消耗。
* **版本冻结与防漂移**：评估前通过 `evals/prepare_evaluation.py --initialize` 对 `src/sleeplens/` 源码、提示词、知识库（`knowledge_sha256`）及开发题集计算 SHA-256 哈希并生成候选快照（如 `artifacts/candidate-v25-01.json`）；`run_formal_evaluation.py` 在运行前强制校验文件哈希，若发生任何代码或文本漂移则拒绝执行。

### 4.2 数据分割与防泄露隔离
* **数据分割（10 题知识集 + 6 题端到端补充集）**：
  * **公开开发知识集（7 题，位于 `evals/formal/knowledge_development.json`）**：覆盖单段直答（`K01`）、多段产品规则与门槛（`K02`）、同义改写与有界数量（`K03`）、专业术语与范围边界（`K04`）、多源情境差异（`K05`）、知识库缺失拒答（`K06`）及跨源推理与测量局限（`K07`）。该 7 题经过逐条原文核验，确认所有预期证据 ID（`B1:Validity`、`B2:Coverage`、`B2:Comparison`、`H2:Caffeine`、`H3:CBTI`、`H2:Naps`、`H4:FirstSteps`、`H1:AdultDuration`、`H1:Quality`）均存在于 `sleep-knowledge-v6` 且适用范围一致。
  * **未见留出知识集（3 题，独立隔离保管）**：由未参与本轮提示词/代码修改的组员独立编写与保管，不写入仓库开发 JSON，仅在最终候选版本冻结后运行一次；若提前用于诊断或修改，则立即转为开发题并重新补充留出题。
  * **补充端到端（E2E）开发用例（6 题）**：覆盖 `P01` 正常两周比较、`P02` 缺失记录拒绝比较、明确单日覆盖侧栏整周、滑动窗口与跨夏令时单日、无记录/未来日期拦截及离线测试桩异常注入。

### 4.3 运行条件与评分口径
* **运行条件**：每道题在独立的 `ChatSession`（Fresh Session）中执行，清零历史对话与证据缓存；测试基准日期固定记录实际执行日期（`Europe/Berlin` 时区）；预算控制设为单轮最多 3 次模型请求、2 次工具执行，全局默认上限 21 次请求与 `60000` 已知 Tokens（响应后检查停止阈值）。
* **评分口径与分母规则**：
  * **多维度二元评分（`pass` / `fail` / `na` / `pending`）**：涵盖证据送达（`evidence_available`）、回答正确与主张支持（`answer_supported`）、引用支持（`citations_supported`）、适当保留结论（`appropriate_abstention`）、工具选择与参数（`tool_choice`）及相关性（`relevance`）。
  * **严格分母计算**：执行异常（`error`）和预算不足未运行（`budget_stopped` / `not_run`）绝不自动剔除出总体统计：
    * **总体开发集通过率** ＝ `案例级全部适用维度均 pass 的题数 / 计划总题数（7）`
    * **单维度适用通过率** ＝ `该维度 pass 题数 / (已执行题数 − 该维度标为 na 的题数)`

### 4.4 离线工程验证（已有基线证据）
* 在开展真实模型评估前，项目已完成 519 项离线确定性回归测试（`pytest -q`，耗时 14.31 秒，全部通过）及离线 CLI 数值复算，验证了 `P01`（两周均值 `390.0` vs `420.0` 分钟，差值 `-30.0` 分钟）与 `P02`（本周 `3/7` 有效夜，覆盖率 `42.9%`，均值 `390.0` 分钟，正确触发 `partial_data` 与 `insufficient_data` 拒算差值）的底层计算精确性。*注：该 519 项测试使用模拟客户端，仅证明工程逻辑无误，不代表真实大模型的语义准确率。*

## 6. 局限性与未来改进方向（Limitations & Next Steps）

1. **检索与上下文长度权衡**：当前 H 类知识检索基于规则词表（`TOPIC_TERMS`）与精确词干匹配，面对长尾同义表达或跨领域隐喻时可能出现检索召回不足（`no_results`）；同时每轮加载基础规则与 Skill 文本带来较高的基础 Prompt Token 开销（历史少量记录显示单轮上下文较重，需结合实测数据评估缓存或精简收益）。
2. **数据与临床外推边界**：所有测试均基于 `2026-10-12` 至 `2026-10-25` 的 42 条合成数据，且知识库主要面向 18–60 岁一般成年人群。系统无法替代多导睡眠监测（PSG）或临床诊断，也不适用于儿童、青少年、孕期人群或需要药物/睡眠限制处方的患者。
3. **单轮与短时记忆限制**：当前对话上下文仅保留近期有限成功回合（最近 4 轮），且不支持跨会话持久化、真实穿戴设备 API 同步或主动健康提醒。
4. **评估样本规模限制**：受课程项目周期与预算限制，形式化评估采用 7 道开发题 + 3 道留出题 + 6 道端到端用例，能够有效暴露典型工具与引用错误，但尚不足以作为大规模商业上线前的统计显著性或医疗安全认证依据。
